# 인터뷰노트 작성 규칙

**목적: 정보 수집과 가설 검증.** 읽는 사람이 "이 인터뷰로 새로 알게 된 것과, 그것이 우리 가설에 주는 의미"를 바로 알게 한다.
대상: 전문가(Expert) 인터뷰, 고객·유통·의료진 인터뷰, 경쟁사·전직자 인터뷰.

## 필수 구성

| 섹션 | 쓰는 법 |
|---|---|
| **기본 정보** | 인터뷰명, 목적, 일시, 형태, 인터뷰이(익명 코드 + 배경: `Expert A — 前 ○○사 마케팅 임원, 15년`), 인터뷰어, 보안 등급, 소스 |
| **Executive Summary** | `headline`: 가장 중요한 발견 한 문장. `background`: 인터뷰 배경 및 목적 1~2개. `points`: 핵심 발견 3~5개(새로운 정보 위주). `schedule`: 후속 일정 및 To-do 2~4개. 모두 한 줄 개조식. 가설에 주는 의미는 결론 `items`(시사점)에 쓴다 |
| **Key Question별 신규 정보** | 시간순이 아니라 KQ·사안별로 구조화한다. 아젠다 = 사전 Key Question, 필요하면 `groups`로 사안을 나눈다. 각 아젠다에 `question`(KQ 문장)을 넣고, 항목에는 인터뷰이가 말한 사실·수치·사례를 쓴다. 이미 알던 내용보다 **새로운 정보**를 우선한다. KQ 밖의 의외의 발견은 별도 아젠다 "예상 밖 발견"으로 모은다 |
| **가설 검증** | 사전 가설마다 `verdict`(support 지지 / refute 반박 / neutral 중립·불명), `evidence`(근거 요약), `src`. 근거가 한 사람의 의견뿐이면 그렇게 적는다 |
| **결론** | `summary`: 이 인터뷰가 프로젝트에 남긴 것. `items`(시사점): 가설 수정, 추가 분석 필요 영역, 스토리라인 반영점 |
| **To-do** | 후속 확인 과제(데이터로 검증할 수치), 다음 인터뷰에서 물을 질문, 추가 섭외 대상. 담당·기한 포함 |

## 문장 규칙

- **노트 전체를 짧은 개조식(~음 / ~임 / ~함)으로 쓴다.**
- **진술과 사실을 구분한다.** 인터뷰이의 말은 기본이 `S`(진술)다. 별도 자료로 확인한 것만 `V`.
- 수치는 인터뷰이가 말한 그대로 쓰고, 추정이면 "인터뷰이 추정"이라고 쓴다.
- 의견은 "~라고 봄", 사실은 "~임"으로 구분한다.
- 인용할 가치가 있는 발언은 항목 문장에 짧게 따옴표로 넣는다. 원문 전체는 오른쪽 원문 시각 버튼으로 볼 수 있다.

## 컴플라이언스

- 인터뷰이 실명·현 직장은 쓰지 않는다. 익명 코드와 배경만 쓴다.
- 인터뷰이가 현 직장의 비공개 정보(미공개 실적, 계약 조건, 진행 중인 거래)를 말했다면 노트에 옮기지 않는다. `excluded`에 `"redact": true`로 범위만 남기고 사용자에게 알린다.
- 전문가 네트워크 경유 인터뷰라면 해당 기관의 규정을 따른다.

## 발송 전 점검

1. headline이 "새로 알게 된 것"인가 (인터뷰 개요가 아니라)
2. 모든 사전 가설에 판정이 있는가
3. 진술(S)과 해석(I)이 섞이지 않았는가
4. 인터뷰이를 특정할 수 있는 정보가 남아 있지 않은가
5. 후속 질문이 다음 인터뷰 가이드로 바로 쓸 수 있는 문장인가
