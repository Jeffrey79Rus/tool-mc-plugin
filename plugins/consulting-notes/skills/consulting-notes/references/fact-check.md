# 팩트체크 기준

목표: 노트의 모든 문장이 인용한 전사 원문으로 뒷받침되는지 확인하고, 그 결과를 `check`/`note`로 남긴다.

## 절차

1. `build_note.py --check-only --report factcheck.md` 실행
2. 오류(출처 해석 실패·누락) 먼저 해결
3. 리포트의 항목을 하나씩 대조해 판정
4. 문장 수정·출처 확장·화자 정정 후 리포트를 다시 만들어 재확인
5. `--strict` 빌드가 통과하면 완료

## 판정

| 판정 | 기준 |
|---|---|
| `ok` 전사 일치 | 인용 원문이 문장의 모든 요소(주체·행위·숫자·시점·강도)를 뒷받침한다. 오인식 용어를 바른 표기로 옮긴 것은 근거를 `note`에 남기면 `ok` |
| `warn` 확인 필요 | 원문이 불완전하거나 오인식이 심해 해석이 갈린다 / 주체가 불명확하다(누구의 "저희"인가) / 숫자의 단위·기준이 모호하다 / 담당·수락이 원문에 없다 / 날짜의 월·요일이 없다 |
| 문장 수정 | 원문보다 강하거나 넓게 쓴 경우. `warn`으로 넘기지 말고 원문 수준으로 고친다 |

## 자주 나오는 과장 패턴

| 패턴 | 예 | 고치는 법 |
|---|---|---|
| 제안 → 합의 | "괜찮을까요?" → "하기로 했다" | "~을 제안했다" |
| 조건문 → 결정 | "하면 좋을 것 같다" → "하기로 했다" | "~이 긍정적일 수 있다고 봤다" |
| 질문 → 약속 | 예산을 물었다 → "상대가 공유하기로 했다" | 질문 사실만 쓰고, 담당은 `(추정)` + `warn` |
| 범위 확장 | "1월쯤" → "12~1월" | 원문 표현 그대로 |
| 주체 바꿔치기 | 고객이 할 일 → 우리 서비스 | 원문의 주어 확인 |
| 출처 범위 누락 | 핵심 단어가 범위 밖 세그먼트에 있음 | `src` 범위를 넓힌다 |

## 화자

- 전사 엔진이 화자를 구분하지 않으면 화자는 문맥 추정이다. `speakers.inferred: true`.
- 짧은 맞장구("네", "맞아요")가 같은 초에 겹치면 세그먼트 번호(`#id`)로 정정한다.
- 화자가 문장의 핵심(누가 약속했는가)일 때 추정에 의존하면 `warn`으로 둔다.

## 숫자 자동 검사

빌드 스크립트는 노트 문장의 숫자가 인용 원문에 있는지 검사한다. 경고가 나오면,
- 원문에 다른 표기로 있으면(예: "칠백" vs "700") `note`에 근거를 적고 판단한다.
- 원문에 없으면 출처를 고치거나 숫자를 지운다.
